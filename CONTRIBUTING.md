# Contributing

## Workflow

- Keep `main` release-authoritative.
- Perform active work on the agreed feature vehicle.
- Preserve documentation alignment with implementation changes.
- Use non-interactive Git operations.

## Commit Guidance

- Group commits by coherent concern boundary.
- Prefer conventional prefixes such as `feat:`, `docs:`, `fix:`, and `chore:`.
- Avoid mixing unrelated documentation and runtime changes without clear reason.

## Release Guidance

- Use `VERSION.md`, `CHANGELOG.md`, and release-aligned branch movement together.
- Do not treat `main` as a casual work surface.
- Create annotated tags for release events.
